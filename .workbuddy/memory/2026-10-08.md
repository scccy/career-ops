# 2026-10-08

## BOSS 单城扫描节奏/扫描量优化（career-ops）

用户反馈「单城市扫描频率太快 / 过度扫描」——根因：单城扫描量没跟该城每日投递上限挂钩。

改动：
- `boss/boss-extract-3cities.sh`
  - 新增**城市间冷却** `BOSS_CITY_GAP_SECONDS`（默认 600s=10min，0=关闭），第 2 城起先休息再扫，打破 5 城连续无间断扫描的风控信号。
  - 新增**单城扫描量绑定投递上限**：`city_quota()` 读 DB `daily_limit_per_city`；每词 `company-limit = ceil(配额 × BOSS_SCAN_BUDGET_FACTOR(默认1.3) ÷ 该城词数)`，`max-cards = 5×`；配额未配置/为 0 时回退遗留固定值（主轮 40/200，补充轮 30/120）。杭州(60)示例：旧 240 家/1080 卡 → 新 ≈78 家/385 卡。
- `boss/boss-chrome-extract.mjs`
  - 每张卡片点击间隔 1–3s → **3–6s**（`CARD_GAP_MIN_MS/MAX_MS`，可由 `BOSS_CARD_GAP_MIN_MS/MAX_MS` 覆盖）。

注：`api/run?id=N` 只是前端轮询 run 任务状态的 GET 接口；真正的单城扫描动作是 `POST /api/run` 的 `key=scan_city` → 调 `boss/boss-extract-3cities.sh --city <城> --all`。系统只有**每城**投递上限（`daily_limit_per_city`），无每关键词上限；当前是把城上限按词数均分。
