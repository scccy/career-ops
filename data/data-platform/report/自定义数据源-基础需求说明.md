# 自定义数据源 - 基础需求说明

> 状态：设计讨论稿，未进入实现阶段
> 创建日期：2026-07-30
> 关联模块：qpointplay-service-holo（report 报表模块）

## 一、背景

report 报表模块当前已支持事件分析、留存分析、漏斗分析、分布分析、属性分析五种基于 SDK 上报事件的分析模型，统一走 `AnalysisDefinition` → `HologresSqlCompiler` → 类型编译器链路，查询在 Hologres 上执行。

标准分析模型覆盖的是 SDK 数据侧的常规场景。但 SaaS 用户自身还有大量已经计算好的业务数据（订单、用户标签、营收汇总等），存放在用户自有的 MySQL / PostgreSQL 数据库里，由用户自己用 Sqoop / DataX 等工具离线 ETL 完成。这些数据**不属于 SDK 上报链路**，但用户希望在 report 平台上和标准分析一样做可视化图表。

本需求即解决：让用户能把自己离线 ADS 性质的 MySQL / PG 库登记到平台，作为自定义数据源，在 report 上做图表。

## 二、定位与边界

### 2.1 数据源定位

- 注册的自定义数据源**作为用户的离线 ADS 处理**
- 口径、聚合、ETL、数据新鲜度**全部由用户自己负责**（用户自己用 Sqoop / DataX 把多源数据汇到一张登记表/视图里）
- 平台只做：数据源登记 + 字段元数据缓存 + SQL 编译 + 执行隔离 + 可视化

### 2.2 不支持的范围（明确边界）

| 不支持项 | 原因 | 替代方案 |
|---|---|---|
| 跨数据源 JOIN | 跨库 JOIN 性能不可控、口径难对齐 | 用户自己 ETL 到一张表/视图后登记 |
| 跨 SDK 数据 × 自定义数据源 JOIN | 同上，且两套数据语义模型不同 | 同上 |
| 实时数据源（Kafka / 流） | 本期只做离线 ADS | 后续按需扩展 |
| 用户直写 SQL | 安全和性能不可控 | 仅支持低代码模式（选字段 + 聚合 + 筛选 + 分组） |

### 2.3 一个 chart 绑一个数据源

- 一个图表查询永远绑在**一个** `dataSourceId` 上
- 不允许"chart A 用 ds1 + ds2 跨源 JOIN"
- 用户要做跨源整合 → 自己用 Sqoop / DataX 解决

## 三、核心决策

### 3.1 数据源类型

- 本期支持 **MySQL + PostgreSQL** 两种
- 数据源类型在**注册时**确定，存 `custom_data_source.dataSourceType` 字段
- 后端编译时按 `dataSourceType` 选 `Dialect` 实现，**前端不感知方言**

### 3.2 前端公共输入模型保持不变

- `AnalysisDefinition` 作为统一公共输入模型，**不再向下抽象一层**
- 自定义数据源只是新增一个 `AnalysisType` 枚举值 + 一个 spec 分支
- 复用所有公共子结构：`FilterGroup`、`Grouping`、`Metric`、`SortSpec`、`PageSpec`、`TimeRange`、`TimeGrain`

### 3.3 编译器分派

- 自定义数据源**不走** `EventAnalysisCompiler` / `RetentionAnalysisCompiler` 等事件模型编译器
- 新增 `CustomDatasetCompiler`，复用：
  - `FilterGroupCompiler`（筛选是通用的）
  - `BindParameter`（参数化绑定是通用的）
- 不复用：事件模型特有的 `event_name` / `event_count` / `event_code` 概念

## 四、接口契约（草案）

### 4.1 `AnalysisType` 枚举扩展

```java
public enum AnalysisType {
    EVENT,
    FUNNEL,
    RETENTION,
    DISTRIBUTION,
    ATTRIBUTE,
    USER,
    CUSTOM_DATASET  // 新增
}
```

### 4.2 `AnalysisDefinition` 扩展

```java
public class AnalysisDefinition {
    // 既有字段保持不变
    private String schemaVersion;
    private Long appId;
    private AnalysisType analysisType;
    private TimeRange timeRange;
    private TimeGrain timeGrain;
    private List<Metric> metrics;
    private List<FormulaIndicatorSpec> formulaIndicators;
    private FilterGroup filters;
    private List<Grouping> groupBy;
    private List<SortSpec> sorts;
    private PageSpec page;
    private DisplaySpec display;
    private RetentionSpec retention;
    private FunnelSpec funnel;
    private DistributionSpec distribution;
    private AttributeSpec attribute;
    private UserQuery user;

    // 新增
    private String dataSourceId;             // 指向 custom_data_source.id
    private CustomDatasetSpec customDataset; // 自定义数据源独有的配置分支
}
```

### 4.3 `CustomDatasetSpec`（待细化）

存放自定义数据源独有的配置，可能包含：
- 时间字段名（用于 `timeRange` / `timeGrain` 对齐）
- 是否物化、刷新策略
- 其他待定项

### 4.4 `Metric` 字段在自定义场景的行为

- `metrics[].field` 仍保留，但解析路径切换：
  - 事件分析 → `LogicalFieldRegistry.resolve(dataset, field)`
  - 自定义数据源 → `CustomDatasetFieldRegistry.resolve(dataSourceId, field)`
- `metrics[].eventCode` 在自定义场景置空（无事件概念）

### 4.5 数据源注册接口（草案）

| 接口 | 方法 | 路径 | 说明 |
|---|---|---|---|
| 创建数据源 | POST | `/bi/customDataSource/create` | 登记连接信息，拉字段元数据 |
| 列表 | POST | `/bi/customDataSource/page` | 分页查询 |
| 详情 | GET | `/bi/customDataSource/detail` | 详情 |
| 刷新 schema | POST | `/bi/customDataSource/refreshSchema` | 用户 DB 加字段后手动触发 |
| 删除 | POST | `/bi/customDataSource/delete` | 软删 |

> 路径遵循项目规范（驼峰、`/bi` 前缀、分页末尾 `page`、详情 `GET`）。

## 五、后端核心组件

### 5.1 数据源实体

```
custom_data_source
    - id
    - tenant_id           # 跨租户隔离
    - name
    - description
    - data_source_type    # MYSQL / POSTGRES
    - jdbc_url
    - username
    - password_encrypted  # 凭证加密存储
    - schema_name
    - table_name
    - read_only_verified  # 注册时校验只读
    - status
    - created_at / updated_at

custom_data_source_field
    - id
    - data_source_id
    - field_name
    - field_type          # VARCHAR / INT / TIMESTAMP ...
    - semantic_tag        # DIMENSION / METRIC / TIME
    - display_name
    - cached_at           # 上次拉取时间
```

### 5.2 `QueryDialect` 抽象（后端内部，前端不感知）

```java
public interface QueryDialect {
    String quoteIdentifier(String name);
    String dateTrunc(String grain, String expr);
    String castNumeric(String expr);
    boolean supportsFilterClause();
    // 其他方言差异...
}
```

实现：
- `HologresDialect`（现有逻辑迁移）
- `PostgresDialect`
- `MySqlDialect`

`FilterGroupCompiler` 重构为：树遍历 + 操作符分派 + 参数绑定不变，方言相关片段委托给 `Dialect`。

### 5.3 `CustomDatasetCompiler`

职责：
1. 读取 `dataSourceId` → 加载 `CustomDataSource` 实体
2. 按 `dataSourceType` 选 `Dialect`
3. 解析 `metrics[].field` → `custom_data_source_field`
4. 编译 `FilterGroup` → WHERE（委托 `FilterGroupCompiler` + `Dialect`）
5. 编译 `groupBy` → GROUP BY
6. 编译 `timeRange` / `timeGrain` → 时间过滤 + date_trunc 桶
7. 走数据源的 JDBC 连接执行，结果包装 `ResultData<T>`

### 5.4 执行隔离

- 独立线程池（不与主业务线程池共享）
- 硬超时（建议 30s，可配置）
- 行数硬上限（建议 10 万行，可配置）
- 只读账户校验（注册时拒绝非只读账户）
- DDL/DML 静态校验拒绝（防止 SQL 注入式攻击）

## 六、安全约束

| 项 | 约束 |
|---|---|
| 凭证存储 | 连接串、密码加密存储，禁止明文 |
| 账户权限 | 注册时校验只读标识，非只读拒绝 |
| SQL 安全 | 禁止 DDL/DML，仅 SELECT |
| 执行隔离 | 独立线程池 + 超时 + 行数硬上限 |
| 跨租户隔离 | 数据源按 `tenant_id` 隔离，查询前校验归属 |
| 网络访问 | 用户 DB 可能公网 / VPC，平台服务需能访问到 |

## 七、与现有体系的接缝

| 复用 | 不复用 |
|---|---|
| `AnalysisDefinition` 顶层结构 | `EventAnalysisCompiler` |
| `FilterGroup` / `Grouping` / `Metric` / `SortSpec` / `PageSpec` | `RetentionAnalysisCompiler` |
| `FilterGroupCompiler` | `FunnelAnalysisCompiler` |
| `BindParameter` | `DistributionAnalysisCompiler` |
| `ResultData<T>` | `AttributeAnalysisCompiler` |
| `BaseEntity` / `CommonMapper` | `LogicalFieldRegistry`（自定义走独立 registry） |

## 八、待定 / 后续讨论

1. **`CustomDatasetSpec` 细化**：除了时间字段，还需要哪些独有配置？
2. **方言层细节**：
   - MySQL 没有 `FILTER (WHERE ...)`，需用 `CASE WHEN` 等价表达
   - MySQL 没有 `date_trunc`，用 `DATE_FORMAT` 替代
   - PG 的 `::NUMERIC` vs MySQL 的 `CAST(? AS DECIMAL)`
3. **字段语义标签**：`DIMENSION` / `METRIC` / `TIME` 三类是否够用？
4. **结果缓存**：自定义数据源查询结果是否做短 TTL 缓存？key 怎么设计？
5. **资源组隔离**：是否需要给自定义数据源查询分配独立用户 DB 资源组？
6. **指标口径对齐**：自定义数据源的指标和 SDK 指标如果同名（比如都有"活跃用户数"），如何防止前端误用？
7. **数据源失效处理**：用户 DB 下线 / 改密码后，平台如何感知和提示？

## 九、本期范围 vs 后置

| 范围 | 状态 |
|---|---|
| MySQL + PostgreSQL 数据源登记 | 本期 |
| 低代码模式（选字段 + 聚合 + 筛选 + 分组） | 本期 |
| 单数据源查询（不支持跨源 JOIN） | 本期 |
| 字段元数据自动拉取 + 手动刷新 | 本期 |
| 只读账户校验 + 执行隔离 | 本期 |

| ClickHouse / Doris 等其他数据源 | 后置 |
| 跨数据源联邦查询 | 后置（且大概率永不做） |
| 流式数据源 | 后置 |
